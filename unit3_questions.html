QUESTION 01 ⭐ 5 MARKS Topic: Banking High Availability & Server Failover
Core Concept: Multi-AZ Redundancy, Load Balancing & Health Probing
Examination Scenario Prompt:

"A banking application must remain available even if one of its application servers fails. Identify the architectural mechanisms that can be used to provide high availability and explain how they work."

Model Solution & Technical Marking Scheme 5 Key Points
1
Core Architectural Mechanism

Deploy a Multi-Availability Zone (Multi-AZ) Active-Active Architecture with an Application Load Balancer (ALB), stateless application servers across distinct data centers, and multi-AZ database clustering.

2
Application Load Balancer & Health Checks

The ALB distributes user HTTP/S traffic across multiple backend server instances in Availability Zones AZ-a and AZ-b. It transmits synthetic health check pings every 5 seconds.

3
Automatic Fault Isolation & Draining

When an application server crashes, the ALB detects failed health checks, halts traffic forwarding to that instance within seconds, initiates connection draining, and routes 100% of traffic to healthy instances.

4
Stateless Session Offload

User authentication session state is externalized into an in-memory distributed cache (e.g., Amazon ElastiCache Redis) rather than stored locally in server memory, so users experience zero session disruption during server failure.

🎯 Exam Key: Key points for 5 marks: 1. Multi-AZ redundant deployment; 2. Load Balancer health check detection; 3. Stateless app tier with ElastiCache/Redis; 4. Zero session disruption.
Exam Architecture Visual
✎ Pen & Paper: Draw Route 53 on top -> ALB distributing to AZ-a Server and AZ-b Server -> Failed Server crossed out with red X -> Traffic routed to AZ-b -> Shared Redis & Multi-AZ DB.
QUESTION 02 ⭐ 5 MARKS Topic: Heterogeneous System Interoperability via SOA
Core Concept: Service-Oriented Architecture (SOA), ESB & Platform Neutrality
Examination Scenario Prompt:

"A company wants its inventory system to communicate with external payment and shipping services developed using different technologies (Java, .NET, Node.js). Explain how SOA can provide interoperability between these systems."

Model Solution & Technical Marking Scheme 5 Key Points
1
Core SOA Interoperability Principle

SOA achieves platform and language neutrality by abstracting business logic behind standardized, platform-independent service contracts (WSDL / OpenAPI / JSON Schemas).

2
Standard Protocol Mediation

Components communicate using universal, vendor-neutral protocols (REST over HTTP, SOAP over XML, or JSON over HTTPS) rather than platform-specific RPC or binary protocols.

3
The Role of Enterprise Service Bus (ESB)

An ESB acts as the intelligent integration backbone: 1. Protocol Transformation (e.g. converting Inventory REST/JSON to Shipping SOAP/XML); 2. Data Transformation (mapping XML schemas to JSON objects); 3. Message Routing.

4
Loose Coupling Advantage

Services have zero knowledge of each other's programming languages, operating systems, or internal database schemas. Modifying or replacing the payment provider requires zero changes to the inventory code.

🎯 Exam Key: Key points for 5 marks: 1. Define Service Contract & Platform Neutrality; 2. Detail the 3 roles of the ESB (Protocol translation, data mapping, routing); 3. Contrast tight coupling with loose coupling.

QUESTION 03 ⭐ 5 MARKS Topic: Large-Scale Video Processing via Parallel Cloud Pipelines
Core Concept: Task-Level Parallelism, Message Queues & Chunking Pipeline
Examination Scenario Prompt:

"A video-processing company receives thousands of raw videos daily that must be transcoded into multiple bitrates and formats. Explain how parallelization and cloud resources can be combined to minimize total processing time."

Model Solution & Technical Marking Scheme 5 Key Points
1
Parallel Decomposition Strategy

Employs two levels of parallelization: 1. Macro (Task-Level Parallelism): Process multiple distinct video files simultaneously; 2. Micro (Data-Level Parallelism): Split long videos into 10-second segments/chunks using FFmpeg.

2
Decoupled Message-Driven Architecture

Raw videos upload to Amazon S3. An S3 event triggers an Amazon SQS message queue holding pending transcoding tasks.

3
Elastic Parallel Compute Fleet

Auto-Scaled worker instances (EC2 Spot instances or AWS Lambda functions) consume chunks from the queue concurrently. 100 worker nodes transcode 100 chunks in parallel in 1 minute rather than 100 minutes sequentially.

4
Aggregation & Stitching Phase

Transcoded segments are assembled by an Aggregator process, verified for audio-video synchronization, and saved back to S3 for CDN distribution.

🎯 Exam Key: Key points for 5 marks: 1. Explain Video Chunking (Data Parallelism); 2. Detail S3 -> SQS -> Worker Nodes pipeline; 3. Mention Amdahl's law and Embarrassingly Parallel scaling; 4. Highlight Spot instance cost savings.

QUESTION 10 ⭐ 5 MARKS Topic: Weather Forecasting Parallel Computing Pipeline
Core Concept: Domain Decomposition, Cloud HPC & MPI Parallel Grid
Examination Scenario Prompt:

"A weather forecasting organization needs to process millions of atmospheric calculations within a strict 30-minute window. Explain how parallelization in cloud applications can be used to reduce the processing time."

Model Solution & Technical Marking Scheme 5 Key Points
1
Spatial Domain Decomposition

The Earth's atmosphere is mathematically divided into a 3D grid of millions of discrete cubic cells (latitude, longitude, altitude).

2
Data-Parallel Processing

Each grid subdomain is assigned to an independent compute node in a cloud HPC cluster (e.g. AWS ParallelCluster with C6i compute-optimized instances).

3
Inter-Node Synchronization via MPI

At each simulation timestep, boundary conditions (wind, pressure, humidity) between adjacent cells must be exchanged using low-latency Message Passing Interface (MPI) over AWS Elastic Fabric Adapter (EFA).

4
Amdahl's Law & Cloud Scaling

By parallelizing 98% of the simulation routines across 1,024 compute cores, total computation time is reduced from 20 hours sequentially to under 12 minutes in parallel.

Examination Scenario Prompt:

"An enterprise wants to deploy a customer relationship management (CRM) solution. Analyze whether they should choose IaaS, PaaS, or SaaS, and illustrate the shared responsibility model across all three models."

Model Solution & Technical Marking Scheme 5 Key Points
1
SaaS Recommendation for CRM

Recommend SaaS (e.g., Salesforce, HubSpot). The enterprise requires standard business capabilities with zero infrastructure or application code development. SaaS provides fastest deployment and lowest management overhead.

Customer manages OS, middleware, runtime, data, and applications. Provider manages hardware, virtualization, and datacenter. Ideal when custom legacy database engines or custom kernel drivers are mandatory.

4
The Shared Responsibility Model

Security OF the cloud (physical hardware, hypervisors) is the provider's responsibility; Security IN the cloud (data encryption, IAM credentials, firewall rules) shifts based on model depth.

QUESTION 13 ⭐ 5 MARKS Topic: Gmail 8GB Storage & 90% Resource Utilization
Core Concept: Multi-Tenant Resource Pooling & Statistical Over-Subscription
Examination Scenario Prompt:

"In 2004, email providers gave users only 2MB to 10MB of storage. Google disrupted the market by offering 1GB (later 8GB+ free) Gmail storage without purchasing millions of dedicated hard disks. Explain how multitenant cloud resource pooling and the 90% utilization model made this possible."

Model Solution & Technical Marking Scheme 5 Key Points
1
The Historical Dilemma

In 2004, physical storage was expensive. Traditional architectures assigned dedicated disk partitions per user. If 10,000 users were given 1GB, the provider had to buy 10,000 physical GB upfront (95% of which stayed completely empty).

2
Statistical Multiplexing / Over-Subscription

Google realized that while every user was promised 8GB, 90% of users actually consume under 50MB. Google provisioned storage dynamically from a shared multi-tenant cluster file system (Google File System - GFS).

3
The 90% Utilization Paradigm

Instead of running physical disks at 10% average utilization, cloud pooling operates storage arrays at 85-90% utilization. Physical disks are purchased just-in-time as actual data blocks are written.

4
Economic Transformation

Reduced cost per mailbox by 99%, proving that virtualization and elastic cloud pooling fundamentally redefine software business economics.

🎯 Exam Key: Key points for 5 marks: 1. Contrast dedicated static allocation with statistical over-subscription; 2. Define the 90% resource utilization model; 3. Role of distributed file systems (GFS); 4. Just-in-time capacity scaling.
Exam Architecture Visual

QUESTION 17 ⭐ 5 MARKS Topic: SOA vs Microservices Architecture Comparison
Core Concept: Smart Pipes vs Dumb Pipes & Monolithic Bus vs Domain Autonomy
Examination Scenario Prompt:

"Modern cloud applications are increasingly migrating from traditional Service-Oriented Architecture (SOA) to Microservices Architecture (MSA). Contrast both paradigms across database ownership, communication pipes, and deployment autonomy."

Model Solution & Technical Marking Scheme 5 Key Points
1
Core Philosophy: Smart Pipes vs Dumb Pipes

SOA relies on 'Smart Pipes and Dumb Endpoints' (heavy ESB containing business transformation and routing logic). Microservices relies on 'Dumb Pipes and Smart Endpoints' (lightweight REST/gRPC and event meshes with all business logic inside services).

2
Data Storage & Persistence

SOA typically shares a common enterprise database across multiple services. Microservices strictly enforces 'Database-per-Service' (each service owns its private schema and tables; no direct cross-database joins).

3
Deployment Autonomy

In SOA, changes to the central ESB often require synchronized redeployment of multiple dependent systems. Microservices are completely decoupled CI/CD pipelines deployable independently without global coordination.

4
Evolutionary Driver

Microservices evolved from SOA to solve the scalability bottleneck and single point of failure inherent in centralized ESBs.

🎯 Exam Key: Key points for 5 marks: 1. Smart Pipes/Dumb Endpoints (SOA) vs Dumb Pipes/Smart Endpoints (Microservices); 2. Shared DB (SOA) vs Database-per-service (MSA); 3. Centralized ESB vs Decentralized API Gateway.

2. Instruction-Level Parallelism (ILP)

Executes multiple machine instructions concurrently within a single clock cycle using processor hardware pipelining, out-of-order execution, and superscalar execution units.

3
3. Data-Level Parallelism (DLP)

Executes a single instruction simultaneously across multiple data elements (SIMD / Vector operations). Crucial in GPUs and video processing (e.g. AVX-512 instructions).

4
4. Task-Level Parallelism (TLP)

Decomposes a software program into entirely distinct threads or distributed tasks running concurrently on separate processor cores or cloud server instances.

QUESTION 20 ⭐ 5 MARKS Topic: Symmetric Multiprocessing (SMP) vs Multi-Core
Core Concept: Multi-Socket SMP vs Single-Die Multi-Core Architecture
Examination Scenario Prompt:

"A hardware architect must select compute infrastructure for a heavy multi-threaded database. Contrast Symmetric Multiprocessing (SMP) with Multi-Core processors, focusing on cache hierarchy, bus contention, and memory latency."

Model Solution & Technical Marking Scheme 5 Key Points
1
Physical Packaging Difference

Multi-Core integrates multiple independent CPU execution cores onto a single physical silicon die. SMP connects multiple distinct CPU sockets across a shared motherboard system bus.

2
Cache Hierarchy & Latency

Multi-Core cores share an ultra-fast on-die L3 cache with sub-10ns latency. SMP processors must communicate across external system buses (QPI/UPI), resulting in higher inter-socket cache coherence latency.

3
Bus Contention

In SMP, memory requests from multiple sockets compete for the shared system memory bus, creating a bottleneck as socket counts increase. Multi-Core uses fast on-chip crossbar switches with higher bandwidth.

4
Modern Hybrid Architecture

Contemporary enterprise servers combine both: Multi-socket SMP boards where each socket houses a 64-core Multi-Core processor (NUMA architecture).

🎯 Exam Key: Key points for 5 marks: 1. Single-die (Multi-core) vs Multi-socket (SMP); 2. Shared L3 cache vs external bus interconnect; 3. Bus contention comparison; 4. NUMA memory hierarchy.

QUESTION 22 ⭐ 5 MARKS Topic: Amazon RDS Multi-AZ Synchronous Replication
Core Concept: Synchronous Block-Level Replication & Automatic CNAME Failover
Examination Scenario Prompt:

"A primary database instance in Availability Zone A experiences a hardware host failure. Explain how Amazon RDS Multi-AZ deployment provides automated failover with zero data loss using synchronous replication."

Model Solution & Technical Marking Scheme 5 Key Points
1
Multi-AZ Architecture Setup

Amazon RDS provisions a Primary DB instance in Availability Zone AZ-a and an identical Standby Replica in a completely different Availability Zone AZ-b.

2
Synchronous Physical Block Replication

Whenever a transaction commit occurs on the primary, changes are synchronously replicated at the block storage layer to the standby before acknowledging completion to the application. This guarantees RPO = 0 (Zero Data Loss).

3
Automated Failure Detection

Amazon RDS monitors primary health continuously. In the event of host failure, OS failure, or storage corruption, RDS automatically initiates failover.

4
DNS Endpoint CNAME Flip

RDS updates the database endpoint DNS CNAME record to point from AZ-a to the standby in AZ-b. The standby is promoted to primary in typically 60 to 120 seconds with zero application code changes.
